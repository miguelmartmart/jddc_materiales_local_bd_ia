corporativa; no se deshabilita ninguna proteccion ni se reinicia este Windows.

RECORRIDOS DE EMPLEADOS
Recepcion:correo/borrador -> validar contacto/direccion -> aviso sin duplicado
-> revision -> asignacion confirmada. No alta ERP ni envio automatico.
Tecnico:lista autorizada -> direccion y contexto -> evidencia/parte -> confirmar
guardado y sincronizacion. El modo offline requiere desarrollo y politica.
Coordinacion:urgencia -> disponibilidad acreditada -> propuesta de reparto ->
revision humana -> seguimiento de bloqueos/cancelacion. No inferir agenda real.
Compras:articulo/unidad/almacen -> existencias fechadas -> restricciones ->
propuesta de compra revisada. No ordenar compras ni modificar stock ERP.
Administracion:proveedor/periodo -> propuesta de lectura autorizada -> bloques
con evidencia -> contraste -> JSON -> futuro informe PDF segun perfil elegido.
Direccion:pregunta -> definicion de metricas -> calidad/reconciliacion -> analisis
con referencias -> limites e incertidumbre. Prediccion no se supone por tener IA.
Sistemas:incidencia -> separar TCP/TLS/HTTP/auth/app/ERP -> correlacion ->
correccion revisable -> staging -> rollback probado -> cierre con evidencia.
Desarrollo:datos sinteticos -> contrato -> regresion -> artefacto versionado ->
validacion independiente -> publicacion controlada. ERP real no es banco de pruebas.

MEDICION Y CRITERIOS COMUNES
Medir por recorrido:tiempo de completar tarea,errores,duplicados,revision humana,
latencia p50/p95,trabajo en cola,cancelacion,lecturas ERP y coste IA por tarea.
Establecer primero linea base; no declarar mejora porcentual sin antes/despues
comparables. El reloj del navegador,servidor y observacion tienen eventos distintos.
Pruebas de carga solo sinteticas; no reutilizar automaticamente peticiones inciertas.
Estado incierto/desconocido visible en lugar de cero,verde o exito inventado.
